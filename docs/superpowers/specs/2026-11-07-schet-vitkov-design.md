# Спецификация: «Счёт витков» — веб-страница подсчёта витков обмотки по фото

Дата: 2026-11-07
Статус: согласована с заказчиком (разделы 1–4 обсуждены и утверждены)

## 1. Цель

Веб-страница для телефона Android: пользователь фотографирует обмотку силового трансформатора (боковой вид, параллельные линии проводов), проводит пальцем линию поперёк витков, программа автоматически размечает пересечения с проводами, пользователь проверяет и корректирует разметку, сохраняет итоговую картинку с числом витков в галерею.

Ключевой принцип (вариант C, «гибрид»): **машина находит линии — человек подтверждает**. Финальное число всегда за пользователем.

## 2. Пользовательский сценарий

1. **Фото.** Открыть страницу в Chrome на Android (с иконки на главном экране) → кнопка «Сделать фото» (камера) или «Выбрать из галереи». Фото загружается на экран.
2. **Линия подсчёта.** Пользователь проводит пальцем прямую линию **поперёк витков** (перпендикулярно проводам). Линию можно перерисовать до запуска подсчёта. Подсказка на экране: «проводите линию там, где витки видны чётко — по резкому, освещённому участку».
3. **Автоматическая разметка.** Программа ставит метки в местах пересечения линии с проводами и показывает число, например «17 витков». Метки — крупные точки; щипком можно увеличить фото.
4. **Проверка и корректировка.** Осмотр разметки с зумом:
   - тап по лишней метке — удалить;
   - тап рядом с проводом без метки — добавить;
   - кнопки «+1» / «−1» — если крайний виток не виден на линии.
5. **Сохранение.** Кнопка «Сохранить» → итоговая картинка: фото + линия подсчёта + метки + крупное число результата и дата → в галерею телефона (через «Поделиться» или скачивание).

## 3. Алгоритм подсчёта

### Этап 1 (первая версия — простой и прозрачный)

1. Вдоль проведённой линии снимается профиль яркости: для каждой точки линии берётся среднее яркости в узкой полосе перпендикулярно линии (полоса сглаживает шум и мелкие дефекты). Профиль считается **в исходном разрешении фото**, независимо от масштаба на экране.
2. Из профиля вычитается медленная составляющая (скользящее среднее) — убираются тени и плавные блики.
3. Границы проводов = резкие перепады яркости. По сглаженной производной профиля находятся пики → места меток. Соседние пики ближе минимального расстояния сливаются в один.
4. Метки отображаются на линии; результат = число меток.

### Этап 2 (после обкатки этапа 1)

- Измеряется типичный шаг между метками (медиана расстояний), по нему **достраиваются пропущенные витки** — в местах, где граница слабая, но по шагу виток должен быть; такие метки помечаются жёлтым («проверьте»).
- Оценка «шумности» профиля: при плохом качестве (нерезкость, слипшиеся линии) — явное предупреждение «здесь автомат может ошибаться, проверьте с увеличением».

## 4. Платформа и доставка

- **Формат:** одностраничное веб-приложение без сборки и фреймворков: `index.html` (HTML+CSS+JS внутри) + `sw.js` + `manifest.webmanifest` + иконки. Чистый JavaScript и Canvas API.
- **Хостинг:** бесплатный статический хостинг (GitHub Pages или Netlify). Постоянный URL; пользователь добавляет страницу на главный экран («Добавить на главный экран») — запускается с иконки.
- **Офлайн:** service worker кэширует файлы приложения; после первого открытия страница работает без интернета (важно для цеха).
- **Приватность:** вся обработка — на телефоне (Canvas API). **Фото не отправляются на сервер.** Никакой аналитики и внешних запросов, кроме загрузки самой страницы.
- **Камера:** `<input type="file" accept="image/*" capture="environment">` — системная камера без запроса доступа к ней из страницы.
- **Язык интерфейса:** русский.

## 5. Интерфейс (кратко)

- Один экран, шаги 1–5 сценария; крупные кнопки под палец.
- Зум: щипок и двойное касание; перерисовка линии — кнопкой «Заново».
- Метки крупные; при корректировке тап работает в увеличенном масштабе.
- Счётчик результата всегда виден на экране.
- Сохранение: сначала попытка Web Share API (сохранение/пересылка картинки, на Android ведёт в галерею), запасной вариант — скачивание файла.

## 6. Ограничения

- Фото в стрейч-плёнке с бликами непригодны (витки не различимы) — программа предупредит о низком качестве, но не запретит.
- Считаются **видимые витки вдоль проведённой линии**, не «всего витков в обмотке».
- Наклон камеры, нерезкость, слипшиеся линии снижают точность автомата; корректирующая проверка пользователем — обязательная часть процесса.

## 7. Этапность и критерии успеха

- **Этап 1:** сценарий из раздела 2 + алгоритм раздела 3 (этап 1) + доставка раздела 4.
  Критерий: на чётких участках контрольных фото автомат ставит ≈80% меток верно; корректировка занимает 10–30 секунд на фото.
- **Этап 2:** автодостройка по шагу, жёлтые пометки, предупреждения о шуме (раздел 3, этап 2).
- **Проверка:** прогон на 28 контрольных фотографиях из папки «фото обмоток» (в цеховых условиях). По итогам — решение об улучшениях этапа 2 и, при необходимости, краткие рекомендации по съёмке.
